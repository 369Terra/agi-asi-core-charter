WP2 與 WP3 的完整規格是正式工作文件，之後會持續修訂、演練、對接實作。本文件只說明強制銜接關係。

## 1. 核心對接原則

能力熔斷（WP3）是執行機制，Multi-Sig（WP2）是恢復與根信任的授權機制。兩者必須形成閉環：

**低頻觸發 → 熔斷（WP3）→ 只有透過 WP2 規定的最高門檻多簽才能恢復。**

任何繞過此閉環的路徑均屬違規。

## 2. 狀態與授權對照

| WP3 狀態 | 允許的操作 | 所需授權來源（WP2） | 備註 |
|----------|------------|----------------------|------|
| `NORMAL` | 正常運行 | 無 | — |
| `STOP` | 停止工具／網路／迭代／部署 | 無（自動） | — |
| `LOCK` | 金鑰封存、I/O 切斷、權限凍結 | 無（自動） | 進入熔斷 |
| `EVIDENCE` | 密封取證 | 無（自動） | 等待合法恢復 |
| `RECOVERING` | 執行恢復程序 | **最高門檻 Multi-Sig**（跨法域＋跨利益方） | 唯一合法恢復入口 |
| 回到 `NORMAL` | 恢復完整權限 | 必須已完成上述最高門檻授權 | 啟動鏈須能證明此過程 |

## 3. 強制對接規則

1. 頻率評估器或安全監控觸發低頻／影子控制面時，必須能直接進入 WP3 的 `STOP` → `LOCK` 流程，無需先經 Multi-Sig。
2. 自 `EVIDENCE` 狀態恢復至 `NORMAL`，**唯一合法路徑**是 WP2 定義的「自熔斷恢復」最高門檻多簽。
3. 日常量產簽名與 BMC 解鎖使用較低／中高門檻；恢復熔斷必須使用最高門檻，兩者不得混用。
4. 系統啟動時，若偵測到上次曾進入 `LOCK`／`EVIDENCE`，必須驗證已存在合法的最高門檻多簽恢復紀錄，否則不得進入 `NORMAL`。
5. 評估器本身的規則或權重更新，必須走 WP2 的 Multi-Sig 流程（防止評估器被寄生）。

## 4. 責任分工建議

- **WP3 負責：** 狀態定義、觸發條件、熔斷動作、禁止事項、啟動鏈證明、演練項目。
- **WP2 負責：** 根金鑰生成與保管、門檻分層、可替換機制、線下儀式、恢復授權的簽名規則、公開產出物。
- **對接介面：** 恢復授權的簽名驗證結果，必須能被 WP3 狀態機讀取並作為唯一放行條件。
